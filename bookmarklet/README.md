# Shy Safari 同步書籤

在任何電腦打開 [Shy Safari](https://www.shysafari.com/)，按一下書籤，就會載入你最新的設定和紀錄，之後每 30 秒自動保存。資料存在你自己的 Google 試算表裡。

- 不用安裝任何東西，也不用開發人員模式。教室電腦重開機清空也沒關係。
- 書籤跟著你的 Chrome 帳號同步，每天登入 Chrome 後書籤就在。
- 備份存在試算表裡，換電腦也找得回來。
- 程式更新是自動的，書籤每次都會載入最新版。

## 第一次設定（只做一次，約 10 分鐘）

建議用個人的 gmail 帳號做這些步驟。學校或單位的帳號，管理員可能不允許「所有人都能存取」的設定，書籤會連不上。

### 1. 建立試算表

1. 打開 [sheets.new](https://sheets.new) 建立一份新的 Google 試算表，取名「Shy Safari 同步」。
2. 選單「擴充功能 → Apps Script」，會開一個程式編輯器的分頁。
3. 把編輯器裡原本的內容全部刪掉，貼上 [Code.gs](https://raw.githubusercontent.com/wudavid725/quietstudy/main/bookmarklet/Code.gs) 的全部內容。
4. 按 Ctrl + S 儲存。

### 2. 部署成網頁應用程式

1. 在 Apps Script 編輯器右上角按「部署 → 新增部署作業」。
2. 按「選取類型」旁的齒輪，選「網頁應用程式」。
3. 設定：
   - 執行身分：**我**
   - 誰可以存取：**所有人**
4. 按「部署」，再按「授權存取」，選你的帳號。
5. 出現「Google 尚未驗證這個應用程式」時，按「進階」→「前往 Shy Safari 同步（不安全）」→「允許」。這是因為程式是你自己的，沒有經過 Google 審查；它只能存取這份試算表。
6. 複製畫面上的「網頁應用程式」網址，結尾是 `/exec`。

### 3. 把書籤加到 Chrome

1. 回到試算表分頁，重新整理。上方選單會多一個「Shy Safari 同步」，第一次出現可能要等幾秒。
2. 按「Shy Safari 同步 → 取得書籤」。如果又要求授權，照上一步的方式允許。
3. 貼上剛才複製的網址，把藍色的「☁ 同步 Shy Safari」按鈕拖到 Chrome 的書籤列。
4. 確認 Chrome 的「設定 → 你和 Google → 同步處理」有同步「書籤」，其他電腦登入後才會出現這個書籤。

## 每天使用

1. 登入 Chrome，打開 [www.shysafari.com](https://www.shysafari.com/)。
2. **在按「Start」之前**，先按書籤列上的「☁ 同步 Shy Safari」。
3. 如果雲端有比較新的紀錄，Shy Safari 會在同一頁重新開啟一次，可能要再允許一次麥克風。
4. 右下角出現「已同步 時間」就好了。網頁開著時每 30 秒自動保存，關掉分頁前也會再存一次。
5. 幾秒後標籤會縮成一個小圓點，上課時比較不顯眼。滑鼠移過去會顯示同步時間；同步有問題時會自動展開。

點右下角的標籤或圓點可以打開面板：

- **立即同步**：馬上保存一次。
- **備份與還原**：列出最近的備份，每份都附上各班的動物數（例如「A 班：12 隻、B 班：3 隻」），方便找到要的那份。按「還原」回到那個時間點。所有電腦都會改用還原後的版本，還原前的紀錄也會先備份。
- **開啟試算表**：看全部的備份。

## 兩台電腦同時使用

如果兩台電腦都改了紀錄，頁面上方會跳出提示，讓你選「改用另一台的」或「保留這台的」。兩份紀錄都會先存進試算表的「備份」分頁，不會消失。

## Shy Safari 改版時

書籤會檢查 Shy Safari 的資料格式。如果網站改版，資料變成書籤看不懂的樣子，右下角會顯示「已暫停同步」，不會把資料寫進試算表，雲端紀錄保持原樣。這台電腦當時的紀錄會另外存一份備份。

如果 Shy Safari 看起來一切正常，可以在面板按「仍要同步」繼續使用，並通知維護書籤的人更新程式。

## 注意事項

- **書籤裡有你的同步碼**，等於試算表的鑰匙，不要分享給別人。萬一外流，到 Apps Script 編輯器的「專案設定 → 指令碼屬性」刪掉 `SYNC_KEY`，再重新「取得書籤」，舊書籤就失效了。
- **不要手動修改「目前紀錄」分頁**。「備份」分頁可以看，但也不要改裡面的資料欄。
- 「備份」分頁最多保留 200 份，舊的會自動刪除。
- 如果右下角顯示「同步有問題」，點開會說明原因。最常見的是網路斷線，恢復後會自動重試。
- 日後 `Code.gs` 有更新時，要把新的內容貼回 Apps Script 編輯器，再到「部署 → 管理部署作業」→ 鉛筆圖示 →「版本：新版本」→「部署」。網址不會變，書籤不用重做。

## 給維護的人

- `sync.js` 透過 jsDelivr 從 GitHub 的 main 分支載入。push 之後 jsDelivr 可能會快取一段時間，可以用下面的指令清除快取，讓新版馬上生效：

  ```bash
  curl https://purge.jsdelivr.net/gh/wudavid725/quietstudy@main/bookmarklet/sync.js
  ```

- `Code.gs` 改了之後，使用者要照上面的步驟重新部署才會生效，所以盡量讓它保持穩定，新功能優先放在 `sync.js`。`sync.js` 要能搭配舊版的 `Code.gs` 運作，例如舊版的備份列表不附資料時，就逐份讀取來顯示摘要。
- 格式檢查依據的是 2026 年 11 月 Shy Safari 的資料結構，寫在 `sync.js` 開頭的 `SCENES` 和 `CLASS_VALUE_CHECKS`。Shy Safari 新增場景或改格式時，要一起更新。
